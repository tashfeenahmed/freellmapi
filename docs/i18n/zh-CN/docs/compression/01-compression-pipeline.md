# 提示词压缩

[← 返回 README](../README.md) · [文档索引](../README.md) · [API 参考](../api/01-rest-api.md)

长的编程智能体会话反复发送系统提示词、文件读取、命令输出和工具 schema。FreeLLMAPI 能在缓存查找、词元预算和路由之前先压缩请求上下文，这样路由器看到的是缩减后的估算值，更多小上下文模型就能保持符合条件。提供方响应绝不重写。

同一条管线跑在 Chat Completions、Responses、Anthropic Messages 和 Anthropic 词元计数上。压缩**默认关闭**。

## 启用它

在仪表盘 **设置 → 提示词压缩** 里选个模式，或用环境变量引导初始模式：

```env
FREELLMAPI_COMPRESSION=lossless
```

一旦仪表盘里保存过设置，存储的设置优先于环境变量。

| 模式 | 运行内容 |
| --- | --- |
| `off` | 不重写请求。这是总开关；请求头无法开启它。 |
| `lossless` | 重复块去重、空白清理、可逆的同构 JSON 表格编码。 |
| `standard` | lossless 引擎外加命令感知的工具输出过滤和陈旧文件读取取代。 |
| `aggressive` | standard 引擎外加旧轮次浓缩、词汇相关性过滤、可选的硬词元目标。 |

仪表盘还能独立控制各引擎、估算词元自动触发、目标大小、稳定前缀冻结、以及是否信任仓库本地过滤器。

## 逐请求控制

随 `X-FreeLLM-Compress` 发下列值之一：

```text
off | on | lossless | standard | aggressive
```

请求头可关闭压缩或降低操作者配置的模式，但不能提高它。`on` 用配置的模式。响应报告生效模式和估算节省：

```text
X-FreeLLM-Compress: standard; saved~=1840
```

节省用和路由相同的估算 `chars / 4` 核算，所以头部刻意用 `~=`。

## 自适应压缩

配置了 `autoTriggerEstTokens` 且未压缩请求跨过那个估算时，管线即便在正常配置模式更低时也可能用 aggressive 引擎。一旦达到 `targetTokens` 就停。显式请求头在降低允许模式时仍优先。

## 保真度与缓存安全

管线是 fail-open 的。每个引擎独立运行，输出若增大请求、抛异常、或过不了保真度闸门就会被丢弃。闸门要求：

> **性能注记 (cf0c216)：** 受保护跨度检查现在在跨度已知被保留时早退出，避免了逐行热路径上的冗余工作。

- 所有不同的数字字面量和 diff hunks 存活；
- 所有不同的数字字面量和 diff hunks 存活；
- 所有显式约束、安全指令、错误行存活；
- 至少 90% JSON 键存活；
- 至少 95% 其他受保护跨度存活；
- 工具调用和工具结果信封保持有效。

受保护跨度包括代码围栏、URL、文件路径、堆栈跟踪、显式约束、错误行、键值对、结构化工具元数据。

重复的稳定系统前缀在第三次出现后冻结。Anthropic `cache_control` 前缀封顶为 lossless 重写。压缩配置计入响应缓存指纹，所以不同压缩等级的请求永不会共享陈旧缓存条目。

## 工具输出过滤器

内置过滤器理解 Git、包管理器、测试运行器、构建、Docker、搜索工具、JSON、堆栈跟踪的常见输出。它们能去 ANSI 转义序列、折叠重复段、保留匹配行、在字符和行数限制下保留有用的首尾上下文。错误输出受到保守处理。

额外的 JSON 过滤器定义可从下列位置加载：

- `~/.freellmapi/filters/*.json` 供用户自有过滤器；
- 项目里的 `.freellmapi/filters.json`，仅当**信任项目过滤器文件**启用时。

项目过滤器默认关闭，因为仓库可能不受信。

## 设计边界

内置路径是确定性、同步、轻依赖、提供方中立的。它不调用另一个模型、不使用学习式词元剪枝模型、不重写图片、不发布不透明的提供方专属压缩块。那些方法在兼容的上游提供方或智能体运行时拥有上下文状态时可能有用，但跨提供方静默翻译它们会削弱本路由器的 fail-open 和保真度保证。

## 设置、预览与统计 API

认证的管理端可用：

- `GET /api/settings/compression` —— 读取生效配置。
- `PUT /api/settings/compression` —— 更新模式、引擎、限制、信任控制。
- `POST /api/compression/preview` —— 检查压缩输出和各引擎结果，不影响实时统计。
- `GET /api/compression/stats` —— 读取滚动聚合和各引擎的节省与保真度闸门丢弃。

MCP 客户端可用 `compression_stats` 工具读取相同的实时聚合。统计只含计数、耗时、估算节省；请求正文绝不保留。
